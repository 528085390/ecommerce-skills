# 第十步 · 保存链接并标记完成

## 输入与完成条件

- 第 9 步的绑定结果（代绑则要回读证据，用户自绑则要用户确认）。
- 每家指定店铺已核对的我方商品预览地址。
- 本轮采集清单和现有 `商品装修说明.md`。完整装修的第 1–9 步（含 5a）已在说明里记录验收。

缺任一项时记录已完成的成果和其余待办。用户要求只交付某个阶段时，按该阶段验收并记录实际进度。完整装修全部通过后才加 `1-`。

## 核对前台

复用第 9 步实际打开的前台地址和已记录的验收结果，补查未核对的项目。检查对应商品、卖点、标签、轮播与详情、价格、规格及加购状态。无标签时按本品清单验收。用户要求亲自验收时，交预览链接并等待确认。

价格按实际显示的币种和金额记录。若店铺按访客地区换币，结合对应市场核对价格。商品缺货且状态已确认时记录 Sold Out，按本轮约定判断是否需补库存再交付。

## 用脚本归档

确认完整装修的两条线均通过，且下方参数覆盖本轮全部店铺。按商品分别运行，同一目录串行操作。在工作区根目录运行以下命令。

```bash
python3 skill/product-decoration/scripts/finalize_decoration.py "$product_dir" \
  --manifest "$manifest" --date "$accepted_on" \
  --preview "$store" "$verified_url"
```

`accepted_on` 填用户当地的实际验收日期（`YYYY-MM-DD`）。每多一家店铺加一个 `--preview 店铺 网址`。首次运行检查说明里的竞品来源、第 1–9 步状态、交付文件以及素材数量。检查通过后加 `--apply`，脚本将目录加一次 `1-`、同步清单 `folder_name`、写入逐店预览链接，最后标记第 10 步与当前进度。输出中包含最终目录和说明路径。

改名后中断时用同样的参数续跑，已完成记录保留原验收日期。两种目录同时存在时先核对来源再继续。仍需使用的本地路径引用按输出目录同步。历史报告和搜图结果中的原始取材路径保留作为溯源记录。只交付部分阶段时，在原目录记录已验收的成果和链接。

## 常见问题

| 情况 | 处理 |
|---|---|
| 停在绑定前审查、用户还没绑 | 按当下阶段交付，目录维持原名，完成日期留「—」。 |
| 后台已绑定，前台看不到卖点标签 | 记录「后台绑定已核实、前台待核对」。刷新预览一次，确认主题和商品都对得上。仍不行就报告实际结果。 |
| 预览地址打不开 | 报告实际返回，不要换成猜的地址凑数。 |
| 已存在 `1-` 前缀 | 复用当前目录，更新同一份说明，别再加一次。 |
| 新旧两个目录并存 | 核对来源和内容，避免覆盖、误合并或混入其他商品。 |
| 改名后脚本或链接指向旧目录 | 同步清单和引用，重新验证新路径下的链接可打开。 |
| 同商品跨店装修 | 每家店铺分别写预览链接和验收记录。完整范围均通过后统一加完成标记。 |
| 店铺装修通过但采购资料待补 | 先交付已核对的店铺预览，记录第 5a 步实际进度，保留目录原名。 |

## 交付

结束时逐项报告每款真实状态，四件事分开写：模板已上传、商品已绑定、前台已核验、本地已标记完成。有阻塞时保留已验证的成果，指明是哪款、卡在哪一步。
