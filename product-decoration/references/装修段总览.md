# 装修段总览（第 7–10 步）

第 6 步通过后进入店铺装修。SHOPLINE 和 Shopify 的第 7–8 步都在本地编辑，用各自的主题 CLI 上传和回读，可按条件合并。第 9 步根据第 8 步的回读结果，在商品后台或经授权的官方 Admin API 绑定。第 5–5a 步可与店铺装修并行，完整装修在第 10 步汇总验收。

## 一张表看全

| 步 | 做什么 | 进入条件 | 产出 | 验收动作（不通过就不往下走） |
|---|---|---|---|---|
| 7 | 建专用模板 | 商品已在目标店铺上架且后台核对到 ID，CLI 有本店主题权限 | 已核对的主题、底稿和专用模板路径 | 限路径上传、回读专用模板。和第 8 步合并时直接验证成品。 |
| 8 | 填卖点与标签 | 底稿和目标路径已核对，原文来源或留空方案明确 | 本地模板中的卖点和标签 | 上传后回读并与预期比对。SHOPLINE 用 `--verify` 检查整份 JSON。 |
| 9 | 绑定商品 | 第 8 步回读通过，商品 ID 已核对 | 商品记录指向目标模板 | 通过后台或 API 回读绑定值，并核对实际前台。 |
| 10 | 交付与标记 | 绑定、预览和本轮各步骤均已验收，完整装修包含第 5a 步 | 预览链接入说明；目录加 `1-` | 链接能打开、内容对得上、目录内容完整 |

## 每步最容易错的地方

**SHOPLINE 第 7 步**
- `sl` 按凭证里的 currentStore 选店铺，**不看目录、不看前台域名**。先跑 `sl theme list` 看第一行域名。
- 所有命令 400，八成是令牌过期（`sl-profile` 的旧快照也会过期），不是店铺坏了、更不是主题不存在。
- 缺 `theme.schema.json` 会让 CLI 直接退出，三个底稿文件要一起拉。
- 模板名两边店相同，本地副本按店铺分目录，否则互相覆盖。

**第 8 步**
- Shopify 按实际主题里的区块及字段修改。SHOPLINE 只改三个指定字段，同层的 `tiered-pricing-bundle`（多件折扣）不能碰。
- 卖点、标签**照录原文**，不许改写或翻译。竞品把卖点写在详情区时，取详情原文并逐条比对；没有标签就把 `sline` 清空，不留样例文案。
- `text` 和 `text_mobile` 必须同文，转义只能做一次。

**第 9 步**
- 完整装修默认由 agent 绑定。用第 6 步编辑链接和第 8 步模板名，只修改商品的「主题模板」。
- 走后台时在模板上传后打开商品编辑页，读取已保存值。
- 走官方 API 时按同一商品 ID 回读。SHOPLINE 用 `template_path`，Shopify 用 `templateSuffix`。

**第 10 步**
- 预览地址用实际检查过的后台预览地址或官方接口返回的商品地址。
- 完整装修用第 10 步脚本检查和归档。脚本统一更新目录前缀、采集清单和说明。
- 两家店都做时，两条预览链接分开记。

## 装修段自检

第 1–6 步的门槛和全流程凭证清单位于 [开工前置与验收清单](开工前置与验收清单.md)，本节的 1、2 两条与之重复，那份额外的还有采集站、Phalanx、店铺后台和代理四处登录态。

1. **网络**：国内站通、境外后台域不通 → 代理节点问题；两个都不通 → 本地断网。别在断网时判断「商品不存在」或「主题没有」。
2. **CLI 店铺**：`sl theme list` 第一行必须是本轮店铺。切店用 `sl-profile use <别名>`，重新授权用 `sl login --store <后台域名>`（需能弹浏览器的交互终端），成功后 `sl-profile save <别名>`。
3. **素材**：清单 `intro` / `tags` / `details` 的实际状态，决定第 8 步走哪条分支。
4. **商品身份**：第 6 步的商品 ID 和后台编辑页链接，第 9 步全靠它定位。
5. **浏览器**：用 agent 专用 profile（`~/.cache/agent-browser`，CDP 9223），后台和 1688 的登录态都在里面；只有用户明确要求时才用内置浏览器。

## 交付时怎么报告

四件事分开写，不要合并成一句「已完成」：模板已上传、商品已绑定、前台已核验、本地已标记完成。中途失败时保留已完成的部分，指明卡在哪一步、卡在哪个证据上。
