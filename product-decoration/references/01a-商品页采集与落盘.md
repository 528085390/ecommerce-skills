# 第一步附册 · 商品页采集与落盘

第 1 步的执行手册。只做一件事：把用户给的竞品商品页，变成一套可离线复用的素材目录 + 一份结构化清单。全程**禁止 OCR**。

第 1 步的其他内容（命名规则、`商品装修说明.md` 初始化、交给第 2 步的交接物）见[第一步 · 抓竞品信息](01-抓竞品信息.md)。本附册只讲采集和落盘本身。

## 产出结构

每个商品一个文件夹，放在用户指定的输出根目录，默认 `<工作区>/商品数据/`：

```text
1124-手摇应急充电器-hand crank charger/
├── 封面.jpg                              ← 轮播第一张图片的原样副本
├── 轮播图/ 01.jpg 02.png 03.webp …       ← 按页面顺序编号，保留真实格式
├── 详情图/ 01.png 02.gif 03.mp4 …        ← 按描述区 DOM 顺序编号
├── 商品详情_打开后全选复制.html           ← 图片 Base64 内嵌，单独打开可见
└── 商品名称_简介_标签.md                  ← 名称 + 简介 + 多件折扣 + 标签 + 标签 HTML
```

- 目录名 `MMDD-中文关键词-英文关键词`，日期取用户当地采集日期，用户指定命名优先。文件名不能用的字符换成 `-`。
- **保留原始媒体格式**：`.webp`、`.gif`、`.mp4` 原样存。动态 WebP 不要转静态图。
- 封面取轮播第一张**图片**的原样副本（同名同扩展名）。首项是视频时取其后第一张图片；轮播只有视频时省略封面并说明。
- 来源、清单、过程记录放素材目录**之外**（`商品数据/_work/` 或临时目录），不放进交付文件夹。

## 已识别版式的批量提取

在商品页加载出主商品区后，优先运行 `assets/extract_storefront.js`。采集器依页面结构识别版式，自定义域名同样适用。

| 版式 | 识别依据 | 批量提取 |
| --- | --- | --- |
| Shopify Viewkoom 及变体 | `product-info` 的 `ProductInfo-` ID，或同一节配对的 `ProductInfo-` 和 `Slider-Gallery-` | 主轮播、标题、标题下简介、可见标签、`quantity-breaks` 或促销块的 `Buy N / Buy N Get M FREE`、两种详情容器 |
| SHOPLINE Bottle（OS 3.0） | `theme-product-detail[data-section-type="main-product"]` | 主商品标题、主轮播与商品详情。按字段报告已识别的简介、标签和多件优惠 |
| 其他站点或尚未适配的主题 | `audit.layout` 为空 | agent 直接检查页面并填写同一份清单，必要时参考 `assets/extract_product.js` 的选择器 |

在浏览器工具的 Node 会话中运行，`tab` 是已打开的商品标签页。

```javascript
const skill = '<skill 根目录绝对路径>';   // 例如 /Users/you/Documents/skill/product-decoration
const fs = await import('node:fs/promises');
const source = (await fs.readFile(skill + '/assets/extract_storefront.js', 'utf8'))
  .trim().replace(/;$/, '');
const input = {
  source_url: '<用户给的原始 URL>',
  folder_name: '<MMDD-中文关键词-英文关键词>'
};
const manifest = await tab.playwright.evaluate(`(${source})(${JSON.stringify(input)})`);
const pending = Object.entries(manifest.audit.fields)
  .filter(([, result]) => result.status === 'needs_review');
```

浏览器工具读不到本地脚本时，把脚本内容作为字符串传给 `evaluate`。先核对返回的版式、`pending` 和媒体审计，补抓后再写清单。

### 提取范围

1. 主标题：`h1`。
2. 标题紧下方的简介条目：区分 heading 与 body。同一富文本段落里用 `<br>` 分行的，按行拆成多条。
3. 可见标签：保留文字和表情符号，**排除后台隐藏的 tags**。
4. 主轮播：按主滑轨当前顺序取原图或最大可用 `srcset` 地址。去掉尺寸限制参数（`_small`、`_100x100`、`?w=100`），补全 `//` 开头的协议相对地址。视频取真实媒体源。
5. 商品描述：以实际描述容器为边界，按 DOM 顺序提取文本 / 小标题 / 列表 / 图片 / GIF / 视频。
6. 多件优惠：只按页面明示取「件数」和「折扣百分比」。某档只写件数或只显示金额时，仅保留件数。**忽略主价格区的促销百分比和旁边金额，不反推百分比。**

**核心防偏离红线**

- **空占位标签直接跳过**：描述富文本里常有建站残留的无 `src` 的 `<img>` 或空 `<video>`。忽略，不要为它们去翻源码、JSON-LD 或网络请求。
- **禁止逐图网络探测**：图片链接只做字符串清洗，不要反复发请求测「去掉参数能不能访问」。直接产出地址。
- **禁止多轮漫游**：不要「截图 → 点下一张 → 滚动 → 再截图」。首选方案应在 1~2 轮内完成，取数控制在 20~40 秒。
- **顺序以页面展示为准**：接口数据和页面顺序冲突时，用页面顺序。

## Agent 核对与补抓

1. 已识别版式时保留已核对的结果。只检查 `audit.fields` 中待复核的字段，以及页面上发现与脚本结果有差异的字段。标题下有文字、可见标签或优惠区有档位时，逐项与对应数组核对。
2. 陌生版式或脚本无法运行时，从页面确认主商品、主轮播、优惠区和详情边界，按六个字段构建清单。折叠区按需展开，懒加载内容按需滚动，虚拟轮播在必要时逐张查看。只从本商品可见区域采集，保留原文和原媒体地址，全程禁止 OCR。
3. 为每个字段写入 `audit.fields.<字段>`，包含 `status` 和简短的 `evidence`。已取得且已核对内容写 `captured`。独立简介、标签或多件优惠经页面核对确实不存在时写 `absent`，对应数据写 `[]`。脚本没命中、页面未加载全或内容仍有疑点时写 `needs_review`。详情中已有的原文放在 `details`，独立简介按标题下的实际内容记录。
4. 补抓后复核主轮播有效数量和顺序、详情容器选择与有效节点数及媒体顺序。更新受影响的 `audit` 数据和字段依据。没有缩略图的版式可用主轮播的数量指示、有效项或媒体 ID 核验，并记录依据。标题、主轮播和详情是本步必需项。仍待复核时保留清单和实际进度。

### 外部媒体反爬兜底

详情图引用了第三方小众 CDN 时，终端 `curl` 可能因 Fake-IP、防火墙或缺少浏览器指纹反复超时。

1. 浏览器已渲染该图时，从页面按原始分辨率保存/截取到 `商品数据/_work/`；
2. 清单**原生支持本地路径**（`商品数据/_work/07.png` 或 `file:///abs/07.png`）；
3. 落盘脚本遇到本地文件直接拷贝并校验魔数，不再走网络，避免卡死。

## 中间清单

核对后的数据写成 UTF-8 JSON，放 `商品数据/_work/` 或临时目录：

```json
{
  "title": "页面商品名",
  "folder_name": "1124-手摇应急充电器-hand crank charger",
  "source_url": "https://example.com/products/example",
  "intro": [
    {"heading": "✅ 卖点标题", "body": "标题下的原文"}
  ],
  "tags": ["🔌 标签一", "🚗 标签二"],
  "quantity_discounts": [
    {"quantity": 1},
    {"quantity": 2, "discount": "22.4%"}
  ],
  "gallery": [
    {"url": "https://example.com/original.webp"}
  ],
  "details": [
    {"type": "text", "text": "商品详情中的独立段落"},
    {"type": "image", "url": "https://example.com/detail.jpg"},
    {"type": "heading", "level": 2, "text": "详情小标题"},
    {"type": "list", "items": ["条目一", "条目二"], "ordered": false},
    {"type": "video", "url": "https://example.com/detail.mp4"}
  ]
}
```

- `details` 的数组顺序**必须**等于页面描述顺序。图片也可写 `"type": "gif"`。
- 轮播数组可直接放 URL 字符串。
- `intro`、`tags`、`quantity_discounts` 经核对确实缺失时写 `[]`。新清单在 `audit.fields` 记录六个字段的结果。示例 `"intro": {"status": "absent", "evidence": "已核对主商品区标题下方，直接进入价格区"}`。
- 用本地文件替代远程地址时，另存 `source_url` 便于追查。

## 落盘

从**工作区根目录**执行，两个参数：清单路径、输出父目录。商品目录名由 `folder_name` 决定，脚本自己创建。

```bash
ruby skill/product-decoration/scripts/save_product_page.rb \
  商品数据/_work/<清单名>.json 商品数据
```

- 依赖 `ruby`（macOS 自带 2.6+ 即可）。缺 ruby 时见[移植与适配指南](移植与适配指南.md)。
- 模板从 `scripts/../assets/product-feature-tags.html` 相对读取，所以 `scripts/` 与 `assets/` **必须保持同级**，不要单独移动其中一个。
- 有 `audit.fields` 的清单在字段状态、实际内容及页面依据核对通过后才能落盘。历史清单仍可按原格式复用。
- 目标文件夹已存在时脚本会拒绝执行。先核对旧成果再决定覆盖或换父目录。
- 演练已有清单时，第二个参数换成新建的临时父目录，避免误写正式素材。

## 文档规则

**`商品名称_简介_标签.md`**：商品名、标题下简介、多件折扣、可见标签，末尾追加标签 HTML/CSS。

- 多件优惠按 `Buy 2 - Save 22.4%` 格式列在「多件折扣」小节。
- 标签 HTML 以 `assets/product-feature-tags.html` 为模板，替换占位文字。标签多于模板 `<span>` 数时，每多一个加一个同结构 `<span>`；`<style>` 和代码结构不改。

**`商品详情_打开后全选复制.html`**：按原顺序渲染描述中的文本与媒体。

- `详情图/` 每张图以 `data:image/...;base64,...` 嵌进对应 `img src`，保证单独打开也能显示全部图片（含 GIF、动态 WebP）。
- `详情图/` 的下载件保留不删。视频仍用公开媒体地址。
- 正文只放商品描述内容，不放店铺政策、推荐商品等容器外模块。

## 完成检查

逐条验，不要只看脚本「保存完成」：

1. 目录名符合 `MMDD-中文关键词-英文关键词`，顶层有 `轮播图/`、`详情图/`、两份文档。轮播有图片时应有 `封面.<原扩展名>`。
2. 轮播媒体数量等于主滑轨的有效 slide 数，详情块数量与描述容器中纳入采集的有效节点一致。
3. 顶层封面与轮播中第一张图片逐字节一致，原图仍保留在轮播目录。首项为视频时按顺序取下一张图片；全为视频时说明无封面。
4. 详情 HTML 中每张图都内嵌（`grep -c "data:image/"` 应等于详情图数量），解码后与同顺序下载件一致。
5. 所有下载文件非空，扩展名与实际格式一致（按魔数判断，不按文件名猜）。
6. 有标签时核对标签文字、`<span>` 数量和模板样式。
7. 商品目录里只有上述交付项，没有清单、日志、临时文件。

## 踩坑表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 直接请求返回 429 | 独立站限流 | 用浏览器正常打开，从页面读 |
| 导航超时但页面已渲染 | 第三方资源拖住 load 事件 | 看标签页实际 URL 和主标题，已加载就继续 |
| `document.baseURI` 解析报无效 URL | 部分页面的 base 异常 | 按页面协议手工补全 `//` 前缀 |
| 缩略图按钮写着「Load image」 | 按钮文案与媒体无关 | 以主滑轨为准，滑轨里可以有视频 |
| 结构化商品数据的描述为空 | 站点没把描述写进 JSON | 读实际描述容器，单用结构化数据会漏采 |
| 详情图数量比可访问性树多 | 图片无 alt 不进可访问性树 | 按描述容器里的图片节点计数 |
| 某张图终端 403/503 | 第三方 CDN 拦终端 | 走「外部媒体反爬兜底」改本地路径 |
| 变体切换后轮播变了 | 变体关联不同媒体 | 先确认轮播列表完整，记录实际采集范围 |
| 全页抓图数量翻倍 | 缩略图、灯箱、吸底加购区重复引用 | 只从主滑轨和描述容器取 |
| 简介或标签为空 | 页面确实没有独立简介/标签云 | 写 `[]`，不要从别处凑 |

## 已实测案例（供核对，不要照抄参数）

| 商品 | 关键结论 |
| --- | --- |
| Viewkoom 热水器 | 主轮播 `[id^="Slider-Gallery-"]` 与缩略图 10 张一一对应；描述区 24 项媒体（21 WebP + 3 GIF，GIF 在第 6–8 项）；页面无独立简介和标签 |
| Viewkoom 矫姿带 | 三条简介共用一段富文本、`<br>` 分行；多件优惠 `Buy 1 / Buy 2 - Save 22.4% / Buy 3 - Save 30.7%`；描述区 54 块、31 张图全部内嵌 |
| Viewkoom 不锈钢煎锅 | 13 个媒体 ID 顺序一致；详情 17 张图可访问性树未列出，按描述容器采集；四个卖点是同段四行 |
