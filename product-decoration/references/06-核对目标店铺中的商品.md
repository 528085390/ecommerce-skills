# 第六步 · 核对目标店铺中的商品

第 4 步通过 Phalanx 把商品上架到本轮指定的我方店铺。取得发布结果后，在**该平台、该店铺的后台**找到这件商品，记录商品标题、商品 ID 和后台编辑页链接。第 7–9 步依赖这份后台身份信息。按已发布的店铺分别核对，可与第 5 步并行。用户只要求装修已有商品时，直接核对该店铺中已上架的目标商品。

## 按商品 ID 只读核对

先确认本轮目标店铺的后台域名。优先使用第 4 步同一站点成功记录中的 `rel_id`，或用户为本轮提供的后台商品 ID。持有该 SHOPLINE 店铺的 `read_products` 授权时，把 token 注入本机的 `SHOPLINE_ACCESS_TOKEN`，在 Skill 目录运行：

```bash
python3 scripts/check_shopline_product.py \
  --store peakoom.myshopline.com \
  --id 16078057706110210586542925
```

示例是燃油壶嘴的历史记录。实际运行时使用本轮店铺和商品 ID。脚本调用 [SHOPLINE 商品详情 API](https://developer.shopline.com/docs/admin-rest-api/product/product/get-a-product/)，读取商品 ID、标题和上架状态。返回 ID 一致、状态为 `active` 时，将输出的后台编辑页和状态写入说明。收到草稿、归档或状态未知时，记录实际状态，暂停该店铺的后续装修。

缺少 API 授权、接口返回 401／403／404 或接口连接失败时，沿用目标后台的已登录会话。可直接打开 `https://<后台域名>/admin/products/<商品ID>/edit` 定位候选，查看页面中的商品身份和上架状态。

## 后台页面查询

用**全流程共用的 agent 浏览器**（脚本跨平台，profile 可用 `AGENT_BROWSER_PROFILE` 指定，默认 `~/.cache/agent-browser`；`python3 scripts/agent_browser.py --open <后台地址>` 直接新开标签）打开后台，登录态存在这个 profile 里。用户明确要求时才改用别的浏览器工具——只有导航、截图、点击能力的工具没有执行 JS 和 Network 监听，后台列表这类动态渲染页容易读不全。

后台域名和前台域名不是同一个。先确认本轮店铺的后台 handle，再拼后台商品列表地址：

```
https://<后台 handle>.myshopline.com/admin/products
```

- 后台 handle 与前台域名可能不同名，以前台页脚、后台登录页或用户给出的后台地址为准。
- handle 拼错时页面返回 **Store unavailable / This store is currently unavailable**，这不是商品不存在，是域名不对。
- 页面能打开但内容区报 **网络连接问题 / 请等待并刷新页面重试**：是这台机器的网络或代理问题，不是商品问题。先修网络再判断，不要据此认定商品缺失。

网络自检（同一条命令里对比国内站和后台域，能区分「代理挂了」和「店铺挂了」）：

```bash
for u in https://h5api.m.1688.com https://<后台 handle>.myshopline.com/admin; do
  printf '%-50s ' "$u"; curl -sS -m 12 -o /dev/null -w '%{http_code}\n' "$u"
done
```

国内站通、后台域不通 → 代理节点不可用（`curl --proxy` 会报 `CONNECT tunnel failed, response 503`），先切节点。两个都不通才是本地断网。

## 在后台核对

1. 缺少商品 ID 或按 ID 定位失败时，打开 `商品` 列表，用标题里辨识度高的英文关键词搜索。标题可能与竞品或另一家店铺不同。
2. 只保留唯一匹配的结果。**多个相似商品时由 agent 自行比对判定**，不比给用户：以第 1 步落盘的轮播图/封面为基准，逐个比对候选的标题关键词、主图主体结构、规格与价格，选出与本轮商品为同一主体的一条，把排除其余候选的依据（标题差异、主图结构不符、规格/价格不符）写进说明。全部候选都不符时才停下报告，不要默认取第一条。
3. 打开商品编辑页，从地址栏取商品 ID。SHOPLINE 商品 ID 是长串数字，例如 `16077768797010174982362925`。
4. 商品状态要是「已上架」。状态为「未同步」「草稿」时不进入第 7 步，先处理状态。

## 前台核验（辅助证据，不替代后台）

用第 4 步发布结果里的商品链接，或 `https://<前台域名>/products/<handle>` 打开商品页，确认标题、价格、加购状态和页面可访问性。商品 ID 和上架状态以后台接口或编辑页为准。

两个店铺各自维护 SEO 标题，同一件商品在两家前台显示的标题可以不一样。核对时比商品主体（图、卖点、规格），不要要求标题逐字相同。

## 完成后

在 `商品装修说明.md` 记录：

- 目标店铺与后台 handle、上架状态、核对来源（接口或编辑页）
- 我方商品标题、商品 ID、后台编辑页链接
- 前台链接及核验结果
- 第 6 步完成日期

确认到商品即进入第 7 步创建专用模板。多匹配时 agent 自行比对判定并记录依据，不打断用户。查不到或无法确认（全部候选都不符）时，停在本步并报告：目标店铺、后台 handle、Phalanx 发布结果、后台查找结果、候选比对与排除依据、网络自检结果。完成日期留「—」，暂停该商品在该店铺的第 7–10 步。采购资料分支、其他已核对商品和店铺可继续。

## 常见问题

| 情况 | 处理 |
|---|---|
| 后台页面 Store unavailable | 后台 handle 不对。换用户给出的后台地址，或从前台页脚找后台入口。 |
| 后台报「网络连接问题」、商品列表空 | 代理节点不可用。做上面的网络自检，先修网络，不要记为「商品查不到」。 |
| 后台能开、搜不到商品 | 换更短的辨识度高关键词再搜；仍无结果时核对第 4 步发布是否真的落到这家店铺。 |
| 搜出多个相似商品 | 以第 1 步轮播图/封面为基准，比对标题关键词、主图主体结构、规格与价格，自行选出同一主体并记录排除依据；全部不符才停下报告 |
| 商品存在但状态未上架 | 记录实际状态并报告，等状态正常后再进第 7 步。 |
| 平台不是 SHOPLINE | 沿用「后台核对、取商品 ID、记录编辑页链接」的规则，按该平台的后台路径改写本步。 |

- 2026-11-24，手摇应急充电器（SPU `G48YX-HL112402`），目标店铺 Viewkoom、Peakoom。
