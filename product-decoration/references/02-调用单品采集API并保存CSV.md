# 第二步 · 调用单品采集 API 并保存 CSV

进入本步前，验收第 1 步素材，确认本轮平台、店铺以及完整 SPU 或生成 SPU 所需的命名参数。

1. 从 `商品装修说明.md` 取原始竞品 URL，核对已有 CSV 或采集任务。已有相同 URL 的可用结果时直接复用，已有任务仍在执行时继续查看该任务。旧任务显示完成但导出页明确提示数据已清理时，重新提交该 URL。
2. 按 [单品采集 API 文档](../../../api/cj_dlz123_api.md) 直接发 HTTP 请求。优先复用采集站点登录会话（环境变量 `DLZ123_PHPSESSID`）。会话缺失或失效时取账号密码：优先读环境变量 `DLZ123_ACCOUNT` / `DLZ123_PASSWORD`，没有则读 skill 根目录 `独立站产品刊登系统key.rtf` 中的「账号」和「密码」。在同一 HTTP 客户端通过 `POST https://cj.dlz123.cn/admin/index/index.html` 的 `login_name` 和 `login_pass` 登录，保留该站会话，并通过任务列表确认登录成功。凭证仅提交给该采集站点，工具输出和任务记录只记录登录结果。随后向 `POST /admin/alloneurl/oneurl.html` 提交这一个 URL（`testurl`）。平台参数对应竞品来源站，使用已确认的平台值或自动识别 `0`。
3. 提交成功后，通过响应中的任务地址或 `GET /admin/spider/index.html` 查找对应的 URL 或任务 ID。等采集成功后读取 `GET /admin/spider/export/id/{任务ID}.html` 的导出表单，保留原字段和值。Shopify 格式通过 `POST /admin/spider/export.html` 返回 CSV 附件。若提交超时，先查任务列表再决定是否重试。
4. 将服务导出的 CSV 保存为素材目录顶层的 `单品采集结果.csv`。**在进入下一步前，必须将 CSV 的 `Handle` 列全部修改为指定的 SPU 格式**：`店铺id-名字首字母+日期+第几个品`（例如 `G48YX-HL112403`），直接使用用户已确认的完整 SPU。需要组装时，使用用户确认的店铺 ID、名字首字母、商品序号和本轮命名日期。保留其他导出内容，确认 CSV 可解析、含表头和商品记录，并与刚核对的采集任务对应。若导出页列出多款商品，先按本次任务或商品筛选再导出。
5. 验收后在 `商品装修说明.md` 记录 CSV 和第 2 步的实际完成日期，再交接第 3 步录入 Phalanx。登录失效、任务失败或 CSV 未取到时，在第 2 步记录实际状态和原因，完成日期留「—」。续跑前核对 CSV 或任务状态。
