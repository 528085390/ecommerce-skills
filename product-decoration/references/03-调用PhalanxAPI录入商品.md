# 第三步 · 调用 Phalanx API 录入商品

用第 2 步保存的 `单品采集结果.csv`，调用 [Phalanx 商品管理](https://ally.easyambass.com/#/Dashboard) 的商品录入 API。截图中的入口是「商品管理 → SPU 列表 → 批量录入商品」。上传时需提供与 CSV 字段对应的「上传映射配置」和商品文件。录入成功后，将商品交给第 4 步发布到对应店铺。

接口地址、表单字段和响应结构见 [Phalanx 商品录入接口](../../../api/phalanx_product_import_api.md)。用户指定手动录入时，通过「批量录入商品」选择映射并上传最终文件。

## 前置：Phalanx 会话

接口基址 `https://portal.ecom.umcasual.cn/api`，每次请求带当前会话的 `token` 请求头。token 从前端登录会话取，不手写。

- 登录入口 `https://ally.easyambass.com/#/Dashboard`，凭证在 skill 根目录的 `ally.rtf`，或环境变量 `PHALANX_ACCOUNT` / `PHALANX_PASSWORD`（只在本机读取，不写进命令回显和交付文件）。
- 未登录或会话过期时接口报 401 / 未授权 / 返回登录跳转，此时重新登录取新 token 再提交，不要改请求体重试。
- 403 或「没有权限」不是凭证问题，是该账号对目标店铺无权限，需找店主开通。

本地准备时用本轮账号注入 `PHALANX_TOKEN`，在 Skill 目录运行 `python3 scripts/check_env.py --phalanx`。预检调用商品列表 GET，只确认会话与商品读取权限。进入录入前还需读取导入映射并核对本轮权限，发布前另核对本轮站点。

## 录入与验收

1. 解析 CSV，确认所有数据行归属本轮一个 `Handle`，上传映射和表头匹配。区分含变体信息的数据行和仅含 `Handle`、图片地址、图片位置的图片行。保留图片行参与导入，只用有效变体行核对 SKU。
2. 上传前按完整 SPU 回查。已有唯一商品且标题、SKU、规格和价格与 CSV 一致时，复用其内部 ID。已有商品不一致或匹配多条时，记录差异和候选，暂停该商品的录入。上传超时或结果不明时按同样方法回查，确认此前未写入后才重试。
3. 上传后检查响应中的成功数、失败数和警告。用完整 SPU 找到唯一商品并按内部 ID 读取详情。`product_skus` 为空时也按这个流程回查。标题、SKU、规格和价格逐项对上后，记录 SPU、商品内部 ID、SKU 数、录入方式和实际完成日期，再交给第 4 步。

> [!NOTE] 后续数据补充
> 单品 CSV 导入成功后，商品在 Phalanx 中仅包含基础标题、轮播图与规格信息，此时状态为「无采购链接 / 0 RMB / 0 g」。在完成第 5 步 1688 以图搜同款后，必须执行 [第 5a 步 · 在 Phalanx 补充采购与 ERP 信息](05a-Phalanx补充采购与ERP信息.md)，将采购链接、成本价、重量、供应商与海关编码补齐。
