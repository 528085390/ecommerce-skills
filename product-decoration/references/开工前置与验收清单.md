# 开工前置与验收清单

这份文档只回答四个问题：**开跑前用户要给什么、机器上要有什么、每步谁验收、缺东西时怎么问**。具体操作仍看第 1–10 步各自的文档。

执行前检查本步必需条件。缺项时暂停受影响的步骤，独立的商品、店铺和处理分支可继续。

## 一、开跑前用户必须给的

### 按步骤必须具备的信息

| 信息 | 最晚需要的步骤 | 要求 |
|---|---|---|
| 竞品商品页 URL | 1 | 用户给出的完整单品详情页链接。缺链接时无法采集，续跑可用同一商品的已验收记录。 |
| 我方平台与店铺 | 2 或本轮首个店铺/平台操作 | 用户指定平台和具体店铺。SHOPLINE 优先记录后台域名。信息未齐时仍可做第 1 步及本地准备。 |
| SPU / Handle 命名参数 | 2 | 用户给出的完整 SPU，或店铺 ID、名字首字母、商品序号。按本轮日期和已确认命名生成，例如 `G48YX-HL112403`。 |
| 已选货源的采购和 ERP 参数 | 5a | 采购链接、人民币成本价、单件克重、供应商代码与名称、商品属性、适用海关编码。价格或重量不清楚时先补证据。 |

### 有默认值（用户不说明就按默认走，不必追问）

| 项 | 默认 | 用户可改 |
|---|---|---|
| 审查方式 | 完整装修连续推进至绑定和验收 | 「逐步审查」每步验收后停。「绑定前审查」完成第 8 步后先交用户审查 |
| 谁绑定 | 完整装修由 agent 绑定 | 用户可要求自绑，或指定本轮交付到绑定之前 |
| 装修范围 | 本轮明确指定的商品和店铺 | 多店时每店分别核对，按共享 CLI 的约束执行 |
| 模板名 | `MMDD-英文商品关键词`，关键词从竞品标题取 | 用户指定名称时优先 |

### 可选加速项（有则省事，没有不影响开工）

- 我方商品标题、后台商品链接或商品 ID —— 第 6 步能省一次搜索
- 商品英文关键词 —— 模板名更准
- 指定主题 ID —— 跳过第 7 步选主题

### 输入示例

只做公开采集时，提供单品 URL 即可。完整装修可一次提供竞品 URL、我方平台、店铺、SPU 或命名参数。采购参数可在 1688 确定候选后补齐。

## 二、开工前自检（自己跑，不要拿去问用户）

原则：**只需要查本轮真要用的那几步**。第 1 步依赖网络、带 CDP 的浏览器、ruby 和采集资产；第 2 步依赖采集站会话。CLI、1688 浏览器、代理这三样修起来要靠用户，建议一开跑就一起查掉。

换环境时可在 Skill 目录运行 `python3 scripts/check_env.py --workspace <工作区>`。脚本检查本机运行时、采集资产、浏览器及 CLI 是否可用，`--net` 才额外探测网络。实际目标后台、CLI 当前店铺及 OAuth 有效性、各平台账号权限仍按对应步骤核对。代理 URL 若包含认证信息，运行或转发输出时先避免暴露原值。

| # | 查什么 | 怎么查 | 通过标准 | 不通过说明 |
|---|---|---|---|---|
| 1 | 网络与代理 | 同时 `curl` 国内域和境外后台域，见第 6 步自检命令 | 两个都 200/302 | 只有一个通 → 代理节点问题；都不通 → 本地断网。见第三节「代理」 |
| 2 | 采集站会话 | `GET https://cj.dlz123.cn/admin/spider/index.html` | 不 302 跳登录页 | 会话失效，按第 2 步用 `key.rtf` 重新登录 |
| 3 | Phalanx 会话 | 将本轮账号的会话 token 注入本机 `PHALANX_TOKEN`，在 Skill 目录运行 `python3 scripts/check_env.py --phalanx` | 商品列表 GET 返回业务码 `200`，`data.list` 是数组，空数组也通过 | 缺 token 或业务码 `10000` 时重新登录。读取通过后，按本轮操作核对录入权限与目标站点 |
| 4 | 主题 CLI | SHOPLINE 用 `sl theme list`，Shopify 用 `shopify theme list --store "$store" --no-input` | 输出本轮店铺的主题清单和目标主题 ID | 按第 7 步核对店铺和主题授权 |
| 5 | agent 浏览器 | `python3 scripts/agent_browser.py --status`，再跑一次搜图脚本 | 端口 9223 有响应、打印得出标签页，脚本能取到 `_m_h5_tk` | 没起来 → `python3 scripts/agent_browser.py`；报「缺少 `_m_h5_tk` cookie」→ 窗口里重新登录 |
| 6 | 素材三态 | 读清单的 `intro` / `tags` / `details` | 三者状态明确，能确定第 8 步走哪条分支 | 状态不明先回第 1 步核，不要在第 8 步猜 |
| 7 | 商品身份 | 第 6 步用目标店铺接口或后台编辑页核对 | 唯一商品 + 实际商品 ID + 编辑页链接 + 已上架 | 多匹配 → agent 比对主图/标题/规格并记录依据；未上架 → 暂停该店铺的装修 |
| 8 | 主题 | 第 7 步 `theme list` | 能看到用户指定主题及其 ID，未指定时核对 `[live]` | 看不到时先解决店铺或权限问题 |
| 9 | 采集运行时 | `ruby scripts/save_product_page.rb --help`；确认采集器和标签模板在 `assets/` | 打印用法，`assets/extract_storefront.js`、`product-feature-tags.html` 都在 | 缺 ruby → 见移植指南；缺 assets → 从 skill 包取回，`scripts/` 与 `assets/` 必须同级 |

本轮要发布时，可在环境准备阶段用本轮账号的 `PHALANX_TOKEN` 运行 `python3 scripts/check_env.py --phalanx-site <目标域名>`。通过表示该域名在发布弹窗的站点清单里且有唯一 ID。实际发布结果仍要按商品和站点回读。

自检结果在第一次汇报里列成一行一项的通过/不通过，不要把失败项藏在「进展顺利」里。

## 三、登录态与凭证总表

**文档只写凭证位置，不写值。** 值在 skill 根目录的 `.rtf` 里（或环境变量 `DLZ123_ACCOUNT` / `PHALANX_ACCOUNT` 等），只在本机读取，不复制到任何交付文件、不打印到终端、不贴进对话。换机器或换人接手时，按[移植与适配指南](移植与适配指南.md)配置环境变量与凭证位置，再跑 `python3 scripts/check_env.py` 确认。

网页登录态统一放在 **agent 专用浏览器**（profile `~/.cache/agent-browser`，CDP 9223）里：启动 `python3 scripts/agent_browser.py`，新开页 `--open <URL>`，看状态 `--status`。**默认就用它**，用户明确说「用内置浏览器」才切换。内置浏览器没有执行 JS 和 Network 监听，抓接口、注入、后台动态列表都会读不全。同一 profile 同时只能被一个进程占用，全流程共用一个实例。

| 用途 | 用在哪步 | 位置 / 形式 | 失效表现 | 谁修 |
|---|---|---|---|---|
| 采集站 `cj.dlz123.cn` | 2 | 账号密码在 `独立站产品刊登系统key.rtf`；会话 Cookie `PHPSESSID`，可复用环境变量 `DLZ123_PHPSESSID` | 任务页/导出页 `302` 跳登录 | agent 可自行重登 |
| Phalanx `ally.easyambass.com` | 3、4、5a | 登录邮箱与密码在 `ally.rtf`；接口用前端会话的 `token` 请求头 | 401 / 未授权 / 接口返回登录跳转 | agent 可自行重登后取新 token |
| SHOPLINE CLI | 7、8（上传模板） | `sl login --store <handle>.myshopline.com` 走 OAuth；凭证 `~/.config/configstore/shopline.json`；快照 `~/.shopline-cli/profiles/`，用 `sl-profile list/use/save` 管 | 所有命令 400；快照同样会过期 | **要用户在能弹浏览器的终端里跑 login** |
| 店铺后台（浏览器） | 6、9 | 全流程共用的 agent 浏览器 profile `~/.cache/agent-browser`（CDP 9223）；后台地址 `<handle>.myshopline.com/admin` | 跳登录页 / Store unavailable | 用户在窗口里登录一次；handle 不对要用户给地址 |
| 1688 | 5 | 同一个 agent 浏览器 profile；签名用 cookie `_m_h5_tk` | 脚本报「缺少 `_m_h5_tk` cookie」或滑块验证 | 窗口里手动登录一次 |
| 代理（Clash / 系统代理等） | 6、7、8、9 | 按你本机客户端的监听端口（读 `HTTPS_PROXY` 或系统代理设置，**端口因人而异**），境外域必须走它 | `CONNECT tunnel failed, response 503`；`socket hang up` | **用户切节点**，agent 改不了 |

凭证使用规则：

1. 只从 `.rtf` 或环境变量读取，**不把值写进命令回显、日志、说明文件**。
2. 汇报里只写「已登录 / 凭证过期」，不写账号密码。
3. `.rtf` 是明文，提醒用户不要外发；需要换号时改文件，不改脚本。
4. 凭证失败与权限失败要分开：`400` / `401` 是凭证；`403` / `没有权限` 是账号对该店铺无权限，此时要找店主开权限，重登无用。
5. 一个凭证只提交给它的目标站点，不要跨站复用 Cookie。

## 四、每步谁验收、看什么、不过怎么办

验收分三级，不要混：

- **A 类（机器可判）**：agent 自己跑命令比对，把证据写进说明。不需要打断用户。
- **B 类（需判断或确认）**。需要用户确认可用货源，或满足本轮约定的审查点。
- **C 类（用户操作或本人授权）**。包括本人登录验证、验证码及用户选择自绑。

| 步 | 类 | 验收证据 | 不过时 |
|---|---|---|---|
| 1 抓竞品 | A | 媒体数 = `audit.slideCount`；封面与轮播第一张图片逐字节一致，轮播全为视频时说明无封面；详情内嵌图解码后与下载件一致；全程无 OCR | 定位失败节点补采，不换素材来源、不改文案 |
| 2 CSV | A | CSV 可解析、含表头、有商品记录、对应到本次任务且只有这一件商品 | 查任务状态；导出页提示数据已清理则重新提交 URL |
| 3 录入 Phalanx | A | SPU/SKU 与 CSV 的商品和规格逐项对应 | 核对上传映射配置，不要重传同一份错配置 |
| 4 发布 | A | Phalanx 逐商品逐站点返回最终发布成功 | 仍在处理或失败时记录实际状态，完成日期留「—」 |
| 5 1688 搜图 | A + B | `1688搜图结果.json/.csv` 落盘，`found > 0`；候选交用户看是否可用 | 换更清晰的原图；等索引；重新登录。UI 兜底见第 5 步 |
| 5a 补充 ERP 信息 | A | update 接口返回业务码 `200`，或界面显示「更新成功」 | 记录接口报错或提交结果待确认 |
| 6 核对商品 | A | 实际后台商品标题、ID、编辑页链接及已上架状态；多匹配时由 agent 比对主图主体、标题关键词、规格与价格自行判定，并记录排除依据 | 先排查网络和店铺域名，仍无法唯一确认时暂停该店铺装修 |
| 7 建模板 | A | 专用模板限路径上传后回读通过，合并 7–8 时直接回读最终模板 | 回读缺文件时查 `--only` 路径和主题 ID |
| 8 填卖点 | A，约定审查时加 B | 回读与本地成品和采集原文一致。SHOPLINE 额外用 `--verify` 核对三个指定字段及整份 JSON | 有字段不符时回读定位，只重传该文件 |
| 9 绑定 | A，用户选择自绑时为 C | 后台或 API 的绑定回读证据，用户自绑时用用户回执。还需实际前台预览结果 | 先核对第 6 步商品 ID 和第 8 步模板路径。保存状态不明时回读当前值 |
| 10 交付 | A，约定用户验收时加 B | 本轮各步骤通过；绑定与预览有证据；完整装修目录已加一次 `1-`，说明与清单同步 | 预览或采购补录仍待验收时先记录现状，目录保留当前名称 |

### 用户最终验收看什么

给用户预览链接时，同时列出这份核对项，让他一眼能判：

- 卖点是否在标题下、红色加粗，条数及内容是否与本款实际素材一致
- 标签区是否符合预期（无标签商品为空属正常，不是漏做）
- 轮播图数量与顺序、详情图是否完整
- 价格、规格、加购按钮正常

## 五、缺东西怎么问

一次只问当前缺的那一项，不把清单一次性甩给用户。几句现成的话：

| 缺什么 | 怎么问 |
|---|---|
| 平台 | 「这轮在哪个平台刊登？」 |
| 店铺 | 「在 SHOPLINE 的哪家店？」（只回平台时接着问） |
| 商品身份 | 「后台有这件商品的链接或 ID 吗？没有我去后台搜，可能要给几个候选你确认」 |
| 多个候选 | 「搜到 3 个相似商品，标题和 ID 如下，哪个是这轮的？」 |
| 确认货源 | 「这里是同款候选、已核对的起批价和单件重量，请确认采用哪一款。」 |
| 重授权 | 「CLI 令牌过期了，麻烦你在终端跑一次 `sl login --store <域名>`，成功后回我一句」 |
| 代理 | 「境外后台连不上，代理节点可能挂了，换一个节点后回我」 |

## 六、阻塞时怎么报告

固定三段，不要只说「卡住了」：

1. **卡在哪**：第几步、哪款商品、哪条命令或哪个页面。
2. **证据**：报错原文关键行、HTTP 状态码、自检结果。区分「凭证过期 / 网络不通 / 域名不对 / 内容不符」。
3. **要谁做什么**：需要用户动手的写到可复制的一行命令或一个链接；不需要用户的，说明我下一步自己试什么。

已完成的部分照常保留并说明状态：模板已上传、商品已绑定、前台已核验、本地已标记，四件事分开记。
