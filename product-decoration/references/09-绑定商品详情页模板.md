# 第九步 · 绑定商品详情页模板

把第 8 步上传的专用模板，绑到第 6 步核对到的那件商品上，并回读确认保存成功。

## 目标与执行边界

- 商品编辑页的「主题模板」保存为本轮专用模板。
- 完整装修默认由 agent 绑定。用户要求自绑或约定绑定前审查时交接。
- 绑定操作只修改「主题模板」字段。

## 前置

- 第 8 步回读校验通过，模板位于该商品绑定和预览对应的主题中。若指定的是未发布主题，先确认本轮交付是主题暂存，还是另有授权部署并绑定。
- 复用第 6 步已确认的后台编辑页链接、店铺域名、商品 ID 和上架状态。
- 商品状态是「已上架」。状态为未同步或草稿时先处理状态。需逐步或绑定前审查时，先完成约定的确认。
- 走后台时优先用**全流程共用的 agent 浏览器**（profile `~/.cache/agent-browser`，CDP 9223）。其会话过期时，可复用本机已有的同店铺登录会话。已有获授权的商品 API 凭证时，可从终端执行下文的 API 路径。

## 绑定交接

交给执行者同一店铺的一组信息。包含第 6 步的商品编辑链接和商品 ID、第 8 步回读通过的主题 ID 和模板完整路径，以及下拉框中的选项名。例如，`templates/product.1125-rust-proof-fuel-spout.json` 对应选项 `1125-rust-proof-fuel-spout`。跨店时分别记录各店结果。

由用户绑定时，把状态记为「待绑定」，并提供下面的保存和预览步骤。用户完成后记录绑定回执和实际预览链接。

## 在后台绑定并回读

1. **直接打开商品**。第 8 步上传并回读成功后，打开交接的商品编辑链接，核对店铺域名和商品 ID。这样会重新读取主题模板列表。已打开的旧页面如需刷新，先处理其中的未保存改动。
2. **读取当前选项**。在新打开的编辑页中记录当前「主题模板」。已是目标模板时，可用这次读取作为绑定证据，直接打开实际预览。切换模板时，先记录原选项。
3. **选择并保存**。选择交接的模板名，点击保存（SHOPLINE 用页面顶部「更新」），等未保存提示消失。随后重开同一编辑页，确认「主题模板」仍为本次选项。导航超时或保存状态不明时，先读取同一页面的已保存值，再决定是否重试。
4. **打开实际预览**。从编辑页点击「预览」或「更多 → 预览」，查看出现的新标签页，核对商品标题和第 8 步的卖点、标签，记录实际打开的 URL。分别记「后台已绑定」和「前台已核对」。

## 常见问题

| 情况 | 处理 |
|---|---|
| 下拉框里没有目标模板 | 核对第 8 步记录的店铺、主题和模板路径，再重新打开对应商品编辑页。 |
| 下拉框点开没反应 | 页面有款式表头引导、客服浮窗遮挡。关掉遮挡再展开，确认列表里真有目标项。 |
| 点「更新」后仍显示未保存 | 先用页面顶部的「更新」而不是右下角按钮；窄视窗下客服浮窗会挡住。刷新前确认没有要保留的改动。 |
| 保存了但重开变回默认模板 | 记录实际回读值，确认仍是本轮商品和目标模板后再保存。 |
| 商品编辑链接或 ID 不符 | 回到第 6 步核对本轮店铺和商品。 |
| CLI 与浏览器不是同一家店 | 用后台域名和商品 ID 核对，只在本次确认的店铺操作。别把 A 店的模板名搬到 B 店。 |
| 预览打开的是别的商品 | 商品 ID 与预览 URL 对不上。回编辑页重新取预览链接，不要沿用上一次的记录。 |
| 预览没跳转 | 检查是否开了新标签页。优先记录实际打开的前台地址；我方 slug 与竞品 slug 通常不同。 |
| 导航超时或控制会话断开 | 先列出现有标签页，重新取得该商品的编辑页并读当前选项。已保存的不必重复提交。 |

## 官方 API 授权参考

第 9 步属于本轮交付范围，且该店铺的应用凭证具备商品读写权限时，可走以下路径。先按第 6 步的商品 ID 回读当前值，已匹配时直接核对前台。更新后再查询持久化结果，核对商品及店铺。缺商品 API 凭证时走已登录的商品后台。

- **SHOPLINE**。有 `write_products` 时可用 Admin REST API `v20260901` 的 `PUT /admin/openapi/v20260901/products/{product_id}.json`，只提交 `product.template_path`，值为第 8 步核对的完整模板路径。用商品读取接口回读 `template_path`。Peakoom 当前走已登录的商品后台，官方 API 写入待有商品写权限的凭证时验证。 [商品更新](https://developer.shopline.com/docs/admin-rest-api/v20260901/product/product/update-a-product/) · [商品读取](https://developer.shopline.com/docs/admin-rest-api/product/product/get-a-product/)
- **Shopify**。具备 `write_products` 时优先用 Admin GraphQL。用 `productUpdate(product: $product)` 提交商品 GID（`id`）和 `templateSuffix`。例如 `templates/product.1125-rust-proof-fuel-spout.json` 的后缀是 `1125-rust-proof-fuel-spout`。可直接调用 API，也可用 `shopify store execute --store "$store" --no-input --allow-mutations` 执行带变量的 mutation。检查 GraphQL `errors` 和 `userErrors`，再按同一 GID 回读 `templateSuffix`。 [商品更新](https://shopify.dev/docs/api/admin-graphql/latest/mutations/productUpdate) · [store execute](https://shopify.dev/docs/api/shopify-cli/store/store-execute)

API 路径也要验实际前台效果。优先打开同一商品由后台或接口提供的前台地址，例如 Shopify 的 `onlineStoreUrl`。验收用直接打开的已绑定商品页面，临时指定模板的预览链接只用于检查模板效果。

## 交第 10 步

提供：后台商品 URL、商品 ID、绑定的模板名、实际预览链接、后台已绑定与前台已核对的分别状态。
