# 第一步 · 抓竞品信息

## 输入与交付

输入为用户给出的竞品商品详情页 URL。

执行细节见[商品页采集与落盘](01a-商品页采集与落盘.md)，其中说明了站点版式识别、agent 补抓、清单格式和落盘验收。全程禁止 OCR。

本 skill 自带的采集件：

| 文件 | 作用 |
| --- | --- |
| `assets/extract_storefront.js` | 识别并批量提取 Shopify Viewkoom 版式及其变体、SHOPLINE Bottle 版式 |
| `assets/extract_product.js` | agent 探查页面时可参考的通用选择器 |
| `assets/product-feature-tags.html` | 标签区块的 HTML/CSS 模板 |
| `scripts/save_product_page.rb` | 清单 → 素材目录的落盘脚本（下载、封面、两份文档） |

> `scripts/` 与 `assets/` 必须保持同级。落盘脚本按 `../assets/product-feature-tags.html` 相对读取模板。

交付四项，缺一不算完成：

1. 素材目录（默认 `商品数据/MMDD-中文关键词-英文关键词`），含封面、`轮播图/`、`详情图/`、两份文档；
2. `商品数据/_work/` 下的清单 JSON；
3. 顶层 `商品装修说明.md`；
4. 第 1 步验收结论（数量、顺序、格式比对结果）。

日期取用户当地的采集日期，关键词用简短的商品通用名称，用户指定的命名优先。后续步骤直接复用落盘的媒体和详情 HTML。

## 执行顺序

1. **算好目录名**：`MMDD-中文关键词-英文关键词`。
2. **打开页面**：用全流程共用的 agent 浏览器打开用户给的 URL，确认主商品标题已加载。
3. **提取与补抓**：按[已识别版式的批量提取](01a-商品页采集与落盘.md#已识别版式的批量提取)生成候选清单。对标为待复核的字段，只检查对应页面区域。陌生版式由 agent 按页面填写同一份清单。核对完再写到 `商品数据/_work/`。
   - 该步的 `folder_name` 就是第 1 步算好的目录名，`source_url` 用用户原始链接。
   - 用 `audit.fields` 区分已采集、页面确无此项和仍待复核，结合轮播、缩略图与详情媒体核对。来源或内容仍待复核时保留本步的实际进度。
4. **落盘**：从工作区根目录执行

   ```bash
   ruby skill/product-decoration/scripts/save_product_page.rb \
     商品数据/_work/<清单名>.json 商品数据
   ```

5. **逐项验收**：按附册的[完成检查](01a-商品页采集与落盘.md#完成检查)走一遍，不要只看「保存完成」。
6. **建说明文件**：在素材目录顶层写 `商品装修说明.md`（格式见下）。

## 商品装修说明.md

素材目录落盘后，在顶层创建 `商品装修说明.md`。第 1 步验收后的格式：

```markdown
# 商品装修说明

- [竞品商品页](https://example.com/products/example)
- 我方平台：待确认
- 我方店铺：待确认
- 当前进度：第 1 步已完成，下一步为第 2 步「调用单品采集 API 并保存 CSV」
- 我方商品预览：待核对

| 步骤 | 状态 | 完成日期 |
| --- | --- | --- |
| 1. 抓竞品信息 | 已完成 | YYYY-MM-DD |
| 2. 调用单品采集 API 并保存 CSV | 待开始 | — |
| 3. 调用 Phalanx API 录入商品 | 待开始 | — |
| 4. 调用 Phalanx 批量发布到对应店铺 | 待开始 | — |
| 5. 在 1688 以图搜同款 | 待开始 | — |
| 5a. 补采购与 ERP 信息 | 待开始 | — |
| 6. 核对目标店铺中的商品 | 待开始 | — |
| 7. 创建专用模板 | 待开始 | — |
| 8. 填写卖点与标签 | 待开始 | — |
| 9. 绑定商品 | 待开始 | — |
| 10. 交付与完成标记 | 待开始 | — |
```

用用户给的原始竞品 URL，填写已确认的平台和店铺，用实际验收日期替换 `YYYY-MM-DD`。

- 复用已有素材时，核对来源后更新已有说明，不要新写一份。
- 续跑目录只有旧版 `商品链接.md` 时，改名为 `商品装修说明.md` 并补齐字段，保留原有链接和备注。

## 验收

| 项 | 判据 |
| --- | --- |
| 目录名 | `MMDD-中文关键词-英文关键词`，或用户指定名 |
| 轮播 | 媒体数 = 主滑轨 slide 数，顺序一致，格式保留（webp/gif/mp4 不转换） |
| 详情 | 块数 = 描述容器节点数，顺序与页面一致 |
| 封面 | 与轮播中第一张图片逐字节一致。首项为视频时顺延；全为视频时注明无封面 |
| 详情 HTML | 每张图 Base64 内嵌，解码后与下载件一致；`grep -c "data:image/"` = 详情图数 |
| 简介 / 标签 / 多件优惠 | 有则按页面原文或明示档位记录。确认确无时写空数组。标签 HTML `<span>` 数与标签数一致 |
| 目录洁净 | 只有交付项，无清单、日志、临时文件 |

来源或商品身份有歧义时请用户确认。用户要求逐步审查时，交付素材和验收结论后等待确认。

## 交接给第 2 步

交出四样：说明文件路径、清单 JSON 路径、素材目录、完整商品名 + 简介条数 + 标签数。同时在说明文件里记录竞品 URL、平台、店铺和第 1 步完成日期。平台或店铺可先记为「待确认」，确认后再进入第 2 步。
