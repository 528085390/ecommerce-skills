# 商品页采集与落盘

每个商品在用户指定的输出根目录创建一个文件夹，默认使用工作区的 `商品数据/`。目录名用 `MMDD-中文关键词-英文关键词`，日期取用户当地的采集日期，关键词用简短的商品通用名称，例如 `1119-热水器-water heater`。用户指定目录名时优先使用。完整商品标题仍写入简介文件。输出结构如下：

```text
1119-热水器-water heater/
├── 封面.jpg
├── 轮播图/
├── 详情图/
├── 商品详情_打开后全选复制.html
└── 商品名称_简介_标签.md
```

`轮播图/` 与 `详情图/` 中按页面顺序用 `01`、`02`……编号，并保留下载后的真实媒体格式（例如 `.webp`、`.gif`、`.mp4`、`.jpg`）。不要将动态 WebP 转成静态图片。商品标题中不能用作文件夹名的字符可替换为 `-`。

将轮播中的第一张图片原样复制到商品目录顶层，命名为 `封面` 并使用原扩展名。轮播目录保留原文件和编号。若首项是视频，取其后第一张图片。轮播只有视频时，省略封面并说明。来源、过程记录和临时清单放在商品目录之外。

## 获取方法：只用页面结构与直接媒体地址

采集采用**两级策略**：首选「单次 JS 批量提取 + 并发下载」的快速方案；当遇到特殊复杂页面导致主方案提取不全或失败时，自动退化到「逐步交互式探索」的备用方案。无论哪种方案，均**禁止 OCR**。

### 1. 首选方案（快速通道：单次 JS 批量提取）

遇反爬防护（如 Cloudflare 429 / 动态渲染）需要浏览器时，调用浏览器 Agent 打开页面，等待首屏与动态组件加载完成。

* **禁止多轮漫游交互**：严禁采用“看截图 -> 点下一张轮播 -> 滚动视口 -> 再看截图”的多轮交互漫游（该模式会耗费数十轮 LLM 调用，导致长达数分钟的无谓等待）。
* **单次注入提取**：Viewkoom 优先用 [专用脚本](assets/extract_viewkoom.js)，已覆盖主滑轨视频、同一加粗段落内的多行卖点、可见标签和逐档多件优惠；[调用示例](../product-decoration/references/01-抓竞品信息.md)说明两个浏览器参数及如何写成清单。其他站点可用 `assets/extract_product.js` 作为结构参考，先核对选择器与实际页面。一次性抓取全部结构化数据并返回 JSON：
  1. 从 `h1` 获取商品名；
  2. 提取标题紧下方的简介条目（区分 heading 与 body）；
  3. 提取可见标签（保留文字与表情符号，排除后台隐藏 tags）；
  4. 遍历主商品轮播容器及对应数据源，提取所有 slide 的原图或最大可用 srcset 地址（去除缩略图尺寸限制参数如 `_small`, `_100x100`, `?w=100` 等），视频取真实媒体源；
  5. 定位商品描述容器，按 DOM 出现顺序一次性提取文本（text）、小标题（heading）、列表（list）与媒体（image/gif/video）URL。
  6. 同批读取可见的多件优惠档位（例如 `quantity-breaks`），按页面顺序提取购买件数和该档明示的折扣百分比。某档只写件数或只显示金额时，仅保留件数。忽略价格、具体省钱金额和商品主价格区的折扣，避免从金额推算百分比。

#### 核心防偏离红线（严格遵守）
* **空占位标签静默忽略**：页面描述富文本中经常包含建站人员复制残留的无 `src` 或空 `<video>`、`<img>` 标签。此类无效空标签**必须直接忽略**，严禁为此花费轮次去全局源码、JSON-LD 或网络请求中检索补充。
* **严禁逐图网络探测**：提取出的图片链接只需做字符串清洗（去除尺寸缩放后缀），**严禁**在浏览器中反复发请求测试“去除参数后能否访问”或“带不带 query 的区别”，直接产出地址即可。
* **耗时标准**：首选方案在 1~2 轮内完成提取，页面数据获取时间应控制在 20~40 秒内。

### 2. 外部媒体反爬与网络超时兜底（本地直传通道）

* **痛点场景**：某些独立站的详情图混合引用了外部第三方小众 CDN（例如某些云存储、特定图片服务器），这些域名在宿主终端 `curl` 时可能会因 Fake-IP、防火墙或缺少浏览器指纹而反复超时阻断。
* **兜底方案**：
  1. 若浏览器已正常渲染该图片，可通过浏览器将该图片按原始分辨率截屏或下载保存到 `商品数据/_work/` 临时目录；
  2. 中间清单 `manifest.json` **原生支持本地文件路径**（如 `商品数据/_work/07.png` 或 `file:///path/to/07.png`）；
  3. 落盘脚本 `save_product_page.rb` 遇到本地文件时会自动直接拷贝并核验魔数，不再走 `curl` 网络下载，杜绝超时卡死。

### 3. 备用方案（降级通道：逐步交互式探索）

* **触发降级条件**：
  1. 首选方案执行 JS 报错或提取到的轮播图/详情块数量明显缺失（如遇到高度混淆的 Shadow DOM、强依赖物理手势拖拽的虚拟轮播列表）；
  2. 页面说明处于深度折叠状态且 JS 无法直接读取隐藏节点内容；
  3. 页面内容随视口物理滚动事件才异步插入 DOM。
* **执行方式**：退化为逐步交互模式，逐步滚动页面、切换轮播 slide、模拟点击展开折叠区域，核对页面展示与 DOM 结构后再导出清单。

### 4. 通用规范与红线

1. 接口数据与页面顺序冲突时，以页面实际展示顺序为准。
2. **禁止 OCR**，也不要用视觉模型、图像识别服务或人工转写去补出图片内文字。图片内文字通过保存原图保留；独立文字只来自页面可选择的文本或公开商品数据。任何未能直接取得的内容要如实指出。
3. Shopify 等站点常把描述图片放在 `description.html` 或 `.product__description` 中；也可能在脚本数据、CSS 背景、懒加载属性中提供媒体链接。按实际站点结构选择来源，不假设所有页面都采用同一模板。对商品接口返回的图片数组，仍要和页面轮播核对顺序及视频/GIF。

## 中间清单与生成

将核对后的数据暂存为 UTF-8 JSON，放在临时目录或 `商品数据/_work/`，不要放进商品交付文件夹。格式如下：

```json
{
  "title": "页面商品名",
  "folder_name": "1119-热水器-water heater",
  "intro": [
    {"heading": "✅ 卖点标题", "body": "标题下的原文"}
  ],
  "tags": ["🔌 标签一", "🚗 标签二"],
  "quantity_discounts": [
    {"quantity": 1},
    {"quantity": 2, "discount": "22.4%"}
  ],
  "gallery": [
    {"url": "https://example.com/original.webp"}
  ],
  "details": [
    {"type": "text", "text": "商品详情中的独立段落"},
    {"type": "image", "url": "https://example.com/detail.jpg"},
    {"type": "heading", "level": 2, "text": "详情小标题"},
    {"type": "list", "items": ["条目一", "条目二"]},
    {"type": "video", "url": "https://example.com/detail.mp4"}
  ]
}
```

新清单填写 `folder_name`，`title` 保留页面原文。`details` 的数组顺序必须就是页面描述顺序。图片也可用 `type: "gif"`。轮播数组可直接放 URL 字符串。媒体用可直接访问的 HTTP(S) 地址。通过浏览器取回后，可改用本地文件路径，另保留原始地址便于核查。

在工作区根目录用脚本落盘。第一个参数是上一步已写出的 JSON 文件，第二个参数是**父目录**，默认 `商品数据`，用户指定时替换它。脚本自己用 JSON 的 `folder_name` 在父目录下创建商品目录。可用 `--help` 查看用法。以下是车载暖风机的路径示例，新采集时使用本次写出的清单。

```bash
ruby skill/product-page-capture/scripts/save_product_page.rb \
  商品数据/_work/viewkoom_car_heater_manifest.json 商品数据
```

脚本会并发下载轮播与详情媒体并生成两份文档。遇到下载或格式识别失败时先看报错中的媒体地址，按上文处理失败项，再用同一参数重试。目标商品文件夹已存在时，先检查旧结果再决定如何更新。要演练已有清单时，第二个参数用新建的临时父目录。

## 文档规则

- `商品名称_简介_标签.md`：保存商品名、标题下方简介、多件折扣和可见标签。有多件优惠时列出件数与页面明示的百分比，例如 `Buy 2 - Save 22.4%`。文件末尾追加标签 HTML/CSS。HTML 以 `assets/product-feature-tags.html` 为模板，替换标签占位文字。标签多于模板中的 `<span>` 数量时，每多一个加一个同结构 `<span>`；`<style>` 和其他代码结构不改。
- `商品详情_打开后全选复制.html`：按原顺序渲染商品描述中的文本与媒体。把 `详情图/` 中每张详情图片的原始字节（含 GIF 和动态 WebP）以 `data:image/...;base64,...` 嵌入对应的 `img src`，让 HTML 单独打开时也能显示所有详情图片。保留 `详情图/` 中的下载件。视频仍使用公开媒体地址。HTML 正文仅放商品描述内容。
- 在浏览器中打开 HTML 后可全选并复制为富文本。若目标编辑器过滤内嵌图片、只接受纯文本或不接收视频，如实说明实际粘贴结果。

## 完成检查

核对目录名称、轮播和详情媒体数量、详情 HTML 的节点数量与顺序，以及简介、标签文本、`<span>` 数量和模板样式。检查所有下载文件非空、扩展名与实际格式一致。逐张确认 HTML 图片均已内嵌，解码后与对应下载件一致。确认顶层封面与轮播第一张图片一致。商品目录只保留上述交付项。
