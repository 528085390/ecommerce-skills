# 评价资料整理与生成提示词

- 迁移真实评价时，保留原文、作者、评分、日期和可使用的媒体，按目标模板转换字段。仅导入有权使用的评价；邮箱必须填写合法地址，用户提供时优先使用，否则按作者姓名生成主流邮箱地址（`gmail.com`、`outlook.com`、`icloud.com` 等域名轮换）。
- 用户未交付文案时，Agent 先阅读目标商品的描述、规格、图片和限制，从核实的商品特征出发，为每条生成标题、正文以及测试姓名、评分和日期。邮箱必填（逐条 API 要求），按姓名生成主流邮箱地址并逐条轮换域名，同批不重复。直接写入本批 CSV 并用 `validate-csv --allow-email` 校验。评价文案可讨论适用场景，不编造购买、收货、使用结果、认证或顾客照片。
- 用户指定的语言、时间范围和条数优先。评价草稿逐款核对标题和正文与商品的对应关系。标题和正文需要不同测试样例时，避免仅替换姓名。日期使用用户当地时间且不得填未来日期。
- `assets/local-validation-example.csv` 只用于本地运行检查。准备上线文件时从空模板开始，使用已核对的真实内容和商品句柄。
